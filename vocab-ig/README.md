# CH02C Vocabulary IG

A build root for the Chapter 2C vocabulary workstream, separate from the v2+
structural IG at the repository root. The two share the repository, the
Apptainer image and `input-cache/publisher.jar`, and nothing else.

## Layout

```
vocab-ig/
├── ig.ini                        the publisher entry point
├── input/
│   ├── vocabulary.xml            the ImplementationGuide resource
│   ├── pagecontent/              index, provenance, known issues
│   ├── includes/menu.xml         navigation (Jekyll dies without this)
│   └── resources/                STAGED — gitignored, see below
│       ├── codeSystems/          398
│       ├── valueSets/            422
│       └── conceptdomains/       1
├── output/                       generated, gitignored
└── template/                     generated by the publisher, gitignored
```

## Resources are staged, not authored

Nothing under `input/resources/` is edited by hand. The writer produces the
corpus in `v291-fhir/`, and `tooling/scripts/stage_vocab_ig.py` copies it here.

The copy exists because the publisher's `path-resource` parameter is **not
recursive** and treats every file in a named directory as a resource. Pointing
it at `v291-fhir/` would feed it `utg-write-report.json` and
`conceptdomains-divergences.json`, which are reports, not resources.

Staging does a full replace of each directory, so a resource deleted upstream
cannot survive here and quietly reappear in a build.

## Building

**Remote (preferred — postproc-g, must be run from the Mac):**

```bash
./apptainer/remote-build.sh vocab      # sync, stage, build, fetch
./apptainer/remote-build.sh fetch-vocab  # re-fetch output only
```

Output lands in `output-vocab/` at the repository root. The `vocab` mode
deliberately skips `tooling/preprocess.sh` — that generates v2+ segment and
message pages and has nothing to do with this guide.

**Local:**

```bash
python3 tooling/scripts/stage_vocab_ig.py
GEM_HOME=/home/claude/.gems GEM_PATH=/home/claude/.gems \
PATH="/home/claude/.gems/bin:/home/claude/ruby/arm64/bin:$PATH" \
/home/claude/jdk/bin/java -Xmx8g -jar input-cache/publisher.jar \
  -ig vocab-ig/ig.ini -no-sushi
```

## Two settings that must not be changed casually

**The seven `apply-*` parameters are false.** The base template defaults them
to true, and when true it overwrites version, publisher, contact, copyright,
wg, jurisdiction and license on every resource in the guide. These resources
carry THO's metadata deliberately. Established by smoke test 2026-08-25.

**There are no `special-url` parameters.** The guide's own `url` is under
`terminology.hl7.org`, which makes resources at THO canonicals native to it.
Adding `special-url` was a wrong turn and was corrected.

## The template

This guide uses stock `fhir.base.template#current`, **not** the v2+
`#local-template`. That template carries structural navigation — segment and
message tabs — that has no meaning for terminology resources.

## Terminology access is required

Do **not** add `-tx n/a` to this build. The v2+ builds use it because
`tx.fhir.org` is unreachable from NIST, but this corpus is value sets:
`ValueSetRenderer.genInclude` dereferences the terminology client while
generating narratives, and with `-tx n/a` that client is null. The publisher
then dies with a `NullPointerException` at "Generating Narratives", roughly a
minute in. Verified 2026-09-14.

If terminology access is blocked on the build host, populate
`input-cache/txcache` on a networked machine first and sync it up — the
publisher reads cached responses from there, and `rsync` already carries
`input-cache`.
